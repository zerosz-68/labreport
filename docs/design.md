# 设计取舍

## 起点：一个"填实验报告"的 skill 为什么不通用

最早的版本是一份 `physics-lab-report` 的 skill（Markdown 说明书 + 若干脚本），它有三个**不可移植**的毛病：

| 毛病 | 具体表现 |
|---|---|
| 依赖别的 skill | 说明书开头写着"先读 `S1/word/SKILL.md`，用它的 `read.py`/`audit.py`"——换台机器那个 skill 根本不存在 |
| 依赖外部二进制 | LaTeX→公式要 `pandoc`，转 PDF 要 LibreOffice，少一个就断 |
| 实验知识写死 | 只有"扭摆"一份领域文件，换实验就作废 |

再加上一个隐性毛病：**整个流程靠模型自觉执行**，换个模型/agent 行为就漂。

## 三代演进

| 代 | 形态 | 弱点 |
|---|---|---|
| 1 代 | 胖 skill，依赖别人的 skill | 换环境缺零件 |
| 2 代 | 胖 skill，自带脚本（如常见的"全家桶" skill） | 依赖靠人装、路径靠工具解析、流程靠模型自觉 |
| **3 代** | **CLI 内核 + 薄 skill + 知识卡（本项目）** | 前期要多写代码 |

**切分原则：确定性的事交给程序，需要理解的事交给模型。**

| 谁 | 负责什么 |
|---|---|
| **CLI（本仓库）** | 解析 OOXML（含合并单元格）、生成 OMML、按坐标写值、数值校验、结构自检、转 PDF/PNG——**同样的输入永远同样的输出** |
| **agent（skill 适配页）** | 看照片识别手写数字、判断哪个值放哪里、把计划讲给用户听、看图确认排版 |
| **知识卡** | 每个实验特有的公式、表结构、量级陷阱、参考数据 |

好处：换 agent 只换一页适配说明；换系统由程序自己处理（`os.path`/`shutil.which`/`sys.platform`）；换实验只加一张卡。

## 几个具体取舍

### 1. 表格定位用"物理网格"，不用 `cells[r][c]`

`python-docx` 的 `table.rows[r].cells[c]` 会把合并区域展开成重复对象，下标和真实网格对不上——按它填**必然错位**。
本项目的做法：从 OOXML 的 `w:gridSpan` / `w:vMerge` 计算每个物理格的"锚点"，于是使用者只要写**屏幕上看到的行列**（`row=2,col=5`），合并换算由程序负责。

### 2. 公式自己转，不依赖 pandoc

`pandoc` 在 Windows 上不常装，而"公式必须是 Word 原生公式"是硬要求。于是内置了一个 LaTeX→OMML 转换器，覆盖实验报告里实际会出现的写法。
**验证方式**：拿一份 pandoc 生成的真实产物当答案，逐条做**结构比对**——28/28 逐字一致；另外用 12 条语料外公式确认不退化（求和、积分、平均值、n 次根、不确定度传递）。

### 3. 数据先过校验，再进报告

手写识别一定会有错。与其"填完再人工核"，不如**填之前**就让程序回答：单位对不对、平均值自洽吗、有没有 3σ 离群、按公式重算与预期差多少。
所以 `data.json` 的每个值都要带 `source`（哪张照片、哪一行）——校验失败时**知道该回看哪里**，这是它能闭环的关键。

### 4. 默认只出计划，不落地

让 AI 直接改 docx 有风险：一次误操作可能把排版弄坏。所以 `fill` 默认把"旧值 → 新值"逐条打印出来，人确认后才 `--apply`；全自动场景用 `--auto`。同一套代码两种模式，不需要二选一。

### 5. 自检做成可判定的门槛

`audit` 输出三级结论，`error` 即不可交付：结构被改坏、公式是空的、正文里还有 LaTeX 残留、`{{...}}` 没解析、数据在成品里找不到。
它把"我觉得填好了"变成"**有证据说明填好了**"。

## 不做什么（边界）

- **不看图片**：识别手写数字是 agent 视觉的活，CLI 不做 OCR——所以它在任何环境都能跑，不挑依赖；
- **不编造数据**：识别不出的格子留占位并报告，不猜一个数填进去；
- **不做无模板新建**：本工具是"按模板填 + 自检"，从零写报告是另一件事；
- **不做量纲推导**：`targets` 的 `unit` 只记录，不校验量纲（但 `expected` 比对能抓住绝大多数错误）。

## 已知限制

- `pdf` 在 macOS/Linux 依赖 LibreOffice，**真实转换未在 CI 覆盖**（CI 只验证"没有转换器时优雅降级为退出码 3"）；
- 中文字体：macOS/Linux 需装 Noto Sans CJK / Source Han Sans，否则 PDF 可能缺字；
- LaTeX→OMML 覆盖的是实验报告常用子集，冷门宏（矩阵、多行对齐等）未实现——遇到会退化成文本并提示，不会静默出错。
